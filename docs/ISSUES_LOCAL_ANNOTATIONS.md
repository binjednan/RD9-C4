# تأشيرات المتابعة المحلية وحدود الدليل

`src/issues.js` يحفظ الملاحظات على الجهاز في `c4issues` بالتنسيق v2. لا يغيّر هذا السجل هندسة المجسم أو نتائج تحقق المصدر أو تصنيف التنسيق.

- تأشيرات v1 والسجل السابق في الملف تبقى محفوظة وتظهر كتأشيرات تاريخية؛ لا تُحسب معالجة أو مطابقة حالية.
- التأشير الجديد يحفظ بصمة سياق للهندسة والنوع والمراجع ودرجة تحقق XY لكل عنصر مع إصدار العارض. البصمة لا تثبت صحة المصدر؛ وظيفتها كشف تغير سياق التأشير. تغيير رقم HTML وحده لا يبطل تأشيرًا إذا بقي هذا السياق نفسه.
- تغير الهندسة أو المصدر أو النوع يجعل التأشير تاريخيًا. عند إعادة الحفظ تُحفظ الملاحظة السابقة في `history`، وكذلك عند مسح التأشير الحالي.
- «مطابق للمصدر»، «عولج»، «مقبول» و«ليس تعارضًا» تأشيرات المستخدم للمتابعة المحلية. لا تعني اعتماد تنفيذ في الموقع، ولا تحسم سجل `coordinationReview` أو `componentReview`.
- شريط المتابعة يعرض تأشير المستخدم المرتبط بالسياق الحالي فقط. المسافة المسجلة في التخمينات السابقة ليست قياسًا لانحراف المصدر الحالي، ودرجات q السابقة ليست تحققًا مستقلًا.
- CSV يفصل التأشير الحالي والتاريخي ويُصدّر سياق التأشير وإصداره وبصمته، ولا يسميه حالة موقع.

التحقق المحلي: نجح فحص syntax بواسطة Node. اختبار تخزين محدود أثبت حفظ الملاحظات القديمة، استبعادها من الحالة الحالية، إبطال صلاحية التأشير عند تغير الهندسة/درجة دليل المصدر، الحفاظ عليه عند تغير نسخة HTML فقط، وحفظ التاريخ عند إعادة الحفظ والمسح. هذا لا يغني عن فحص واجهة المتصفح ضمن التكامل الرئيسي.
